lede: 把 T2 的 online softmax 和 T4 的 tl.dot 合在一起：attention 不再生成 S×S 的分数矩阵，显存从 O(S²) 降到 O(S)，速度也因为少搬数据而大幅提升。

## 背景

标准 attention：`P = softmax(QKᵀ · scale)`，`O = P V`。naive 实现要把 `[S, S]` 的 P 写回显存再读出来。S = 8192、32 个 head 时，P 在 fp16 下有 4 GB。FlashAttention 的观察是：**softmax 可以分块、增量地算**，所以只要让一个 program 负责 BLOCK_M 个 query，把 K、V 按 BLOCK_N 一块块流过来，所有中间结果都留在片上。vLLM / SGLang 的 prefill、训练框架的 attention 都基于这个算法。

## 要用到的知识：online softmax

对 query 行 i，维护三个量（fp32）：

- `m`：目前见过的最大分数
- `l`：`Σ exp(s − m)`
- `acc`：`Σ exp(s − m) · v`

来了新的一块分数 `s_blk`（以及对应的 `v_blk`）：

```text
m_new = max(m, max(s_blk))
p     = exp(s_blk − m_new)            # 新块的权重
alpha = exp(m − m_new)                # 旧状态的缩放系数（最大值变大时，旧的指数要整体变小）
l     = l · alpha + Σ p
acc   = acc · alpha + p @ v_blk
m     = m_new
```

全部块处理完之后，`o = acc / l`。这和一次性算完全 softmax 在数学上**完全等价**。

## 要用到的知识：形状与掩码

- q tile：`[BLOCK_M, D]`，循环外加载一次。
- 直接把 K **按转置的形状**加载成 `[D, BLOCK_N]`：`K + cols[None, :] * stride_s + offs_d[:, None]`，这样 `tl.dot(q, k)` 就是 `[BLOCK_M, BLOCK_N]`。
- 无效位置的分数设为 −inf：超出序列长度的 key（`cols >= S`），以及 causal 时 `cols > query 位置`。
- causal 时，query 块 `start_m` 只需要看前 `(start_m + 1) · BLOCK_M` 个 key，循环上界直接截断，省一半计算。
- `p.to(v.dtype)` 后再做 `tl.dot(p, v, acc)`：Tensor Core 需要 fp16 / bf16 输入。

## 题目要求

wrapper 已写好：`grid = (cdiv(S, BLOCK_M), B·H)`，q、k、v、o 形状相同 `[B, H, S, D]` 且连续，D ∈ {16, 32, 64, 128}，S 任意。实现 `flash_attn_fwd_kernel`：

- 支持 `CAUSAL`（constexpr）和自定义 `sm_scale`。
- 与 `F.scaled_dot_product_attention` 在 fp16 下误差 ≤ 1e-2。
- 不能分配或写出任何 `[S, S]` 大小的中间结果。

## 提示

::: hint 1 骨架
```text
定位 (b, h) 和 query 块 → load q
m = -inf, l = 0, acc = 0
for 每个 key 块（causal 时截断）:
    s = q @ kᵀ · scale，无效位置填 -inf
    online softmax 更新（上面 6 行）
o = acc / l → store
```
:::

::: hint 2 常见坑
- 第一轮 `m = −inf`：`alpha = exp(−inf − m_new) = 0`，这是正确的（旧状态本来就是空的）。但如果某一行在**整块**里全是 −inf，`m_new` 也是 −inf，`exp(−inf − (−inf))` 会得到 NaN。本题里每个真实 query 在第一个块就能看到 key 0，所以不会发生；L3 的空分片就会遇到这种情况。
- causal 的比较方向：query 位置 ≥ key 位置才有效（`offs_m[:, None] >= cols[None, :]`）。
- `alpha` 要同时乘到 `l` 和 `acc` 上，漏乘任何一个，结果都会偏。
- 超出 S 的 query 行（最后一个块）要在 store 时 mask 掉。
- `range(0, hi, BLOCK_N)` 的 hi 可以是运行时的值，Triton 支持。
:::

::: hint 3 循环体
```python
for start_n in range(0, hi, BLOCK_N):
    cols = start_n + offs_n
    k = tl.load(K + base + cols[None, :] * stride_s + offs_d[:, None], mask=cols[None, :] < S, other=0.0)
    s = tl.dot(q, k) * sm_scale
    valid = cols[None, :] < S
    if CAUSAL:
        valid = valid & (offs_m[:, None] >= cols[None, :])
    s = tl.where(valid, s, float("-inf"))
    m_new = tl.maximum(m_i, tl.max(s, axis=1))
    p = tl.exp(s - m_new[:, None])
    alpha = tl.exp(m_i - m_new)
    l_i = l_i * alpha + tl.sum(p, axis=1)
    v = tl.load(V + base + cols[:, None] * stride_s + offs_d[None, :], mask=cols[:, None] < S, other=0.0)
    acc = tl.dot(p.to(v.dtype), v, acc * alpha[:, None])
    m_i = m_new
```
:::

## 测完之后

- FLOPs 按 `4·B·H·S²·D`（QKᵀ 和 PV 各 `2·S²·D`，causal 时减半）计算。RTX 5090 实测（B = 4、H = 16、D = 64，fp16，单位 TFLOP/s）：

| S | 非 causal：SDPA / 参考解 | causal：SDPA / 参考解 |
|---|---|---|
| 512 | 116.6 / 116.5 | 58.1 / 68.7 |
| 1024 | 155.2 / 161.3 | 104.5 / 116.5 |
| 2048 | 189.6 / 190.3 | 149.0 / 150.8 |
| 4096 | 211.2 / 203.0 | 186.0 / 175.9 |

  这个只有几十行的版本已经和 PyTorch SDPA 处于同一水平（95–118%）。S = 4096 时略慢，下面几条是继续优化的方向。在 H100 上差距会大一些：那里的 FlashAttention-3 用了 wgmma、TMA 和 warp specialization。
- **exp2 技巧**：把 `sm_scale` 乘上 `log2(e)`，用 `tl.exp2` 代替 `tl.exp`，硬件的 `ex2` 指令更快。官方 tutorial 就是这么做的。
- **causal 的两段循环**：对角线之前的块完全不需要 mask，只有对角块需要。拆成两段循环可以省掉大部分 `tl.where`。
- **把 LSE 存下来**：`lse = m + log(l)`，backward 需要它。L3 会用它来合并多个分片。
- 不同的 `BLOCK_M / BLOCK_N / num_warps / num_stages`：在 D = 64 和 D = 128 下最优值不同。用 autotune 试试。
- 你刚写的就是 **prefill** attention。decode（每次只有 1 个 query）为什么不能直接用它？见 L2。

::: answer 面试追问：FlashAttention 的 FLOPs 没有减少，为什么会更快？
attention 的瓶颈不在 FLOPs，而在 HBM 读写：naive 实现要把 S×S 的分数矩阵和 softmax 结果写出、再读回，字节数是 O(S²)。FlashAttention 把这部分留在 SRAM / 寄存器里，HBM 读写降到 O(S·D)（Q、K、V、O 各读写一次，严格说 K、V 会被每个 query 块重读一遍）。它没有减少计算，减少的是 IO，属于 IO-aware 算法；反而多出了一点重缩放的计算。
:::
