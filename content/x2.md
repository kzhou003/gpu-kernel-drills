lede: 把 C2 的归约结构搬到 Apple GPU：simd_sum / simd_max 负责 simdgroup 内，threadgroup 内存加 barrier 负责组内汇总。用它写出逐行 softmax 和 RMSNorm，并踩一个 MLX 特有的坑。

## 背景

softmax、RMSNorm、LayerNorm 在 MLX 里都有内置的融合实现（`mx.softmax`、`mx.fast.rms_norm`、`mx.fast.layer_norm`）。自己写一遍，是掌握 Metal 归约写法最快的方式，也是今后写新融合算子（比如带量化的 norm、DiT 的 adaLN）的基础。

## 要用到的知识

- **simdgroup 归约**：`simd_sum(v)`、`simd_max(v)` 直接返回 32 个 lane 的和 / 最大值，**每个 lane 都能拿到结果**（相当于 CUDA 里用 `__shfl_xor_sync` 做完一整轮 butterfly）。
- 内建属性：`thread_index_in_simdgroup`（lane）、`simdgroup_index_in_threadgroup`、`threads_per_threadgroup`、`threadgroup_position_in_grid`。
- threadgroup 内存：在函数体中声明 `threadgroup float scratch[32];`，同步用 `threadgroup_barrier(mem_flags::mem_threadgroup)`。
- 两级归约：`simd_sum` → 每个 simdgroup 的 lane 0 写入 `scratch[sg]` → barrier → 每个 simdgroup 都把 nsg 个部分和读回来，再做一次 `simd_sum` → barrier（之后 scratch 才能复用）。
- **地址空间的坑**：MLX 可能把很小的输入数组放在 `constant` 地址空间而不是 `device`。写 `const device T* xr = x + row * n;` 时，遇到小输入会编译失败（`cannot initialize ... 'const device float *' with ... 'const constant float *'`），用 `auto xr = x + row * n;` 就没有问题。本套题的参考解最初就踩了这个坑：只有 shape 为 (1,1) 和 (2,3) 的测试失败了。

## 题目要求

在 `mine/x2_metal_softmax.py` 中补全：

1. `_HEADER`：`template <bool IS_MAX> inline float tg_reduce(float v, threadgroup float* scratch, uint lane, uint sg, uint nsg)`，返回整个 threadgroup 的归约结果（每个线程都要拿到）。
2. `_SOFTMAX`：一个 threadgroup 处理一行，三遍：求 max、求 exp 的和、写出结果。
3. `_RMSNORM`：平方和 → rstd → `x · rstd · w`。

wrapper 已写好：一行一个 threadgroup，线程数为 32–1024，按行长决定。

## 提示

::: hint 1 tg_reduce 的结构
```c++
v = IS_MAX ? simd_max(v) : simd_sum(v);
if (lane == 0) scratch[sg] = v;
threadgroup_barrier(mem_flags::mem_threadgroup);
v = lane < nsg ? scratch[lane] : (IS_MAX ? -INFINITY : 0.0f);
v = IS_MAX ? simd_max(v) : simd_sum(v);
threadgroup_barrier(mem_flags::mem_threadgroup);
return v;
```
:::

::: hint 2 常见坑
- 第二轮只让 simdgroup 0 去归约：其他 simdgroup 拿不到结果，接下来的 `x − max` 就是错的。让每个 simdgroup 都读 scratch 再归约一次，最简单。
- 少了最后那个 barrier：softmax 的第二次 `tg_reduce` 会在别人还在读 scratch 时覆盖它。
- 循环变量和 `ncols`（`constant int&`）的有符号 / 无符号比较：先 `uint n = uint(ncols);`。
:::

::: hint 3 softmax 函数体
```c++
uint row = threadgroup_position_in_grid.x, tid = thread_position_in_threadgroup.x;
uint nthr = threads_per_threadgroup.x, lane = thread_index_in_simdgroup;
uint sg = simdgroup_index_in_threadgroup, nsg = (nthr + 31) / 32, n = uint(ncols);
threadgroup float scratch[32];
auto xr = x + row * n;
float m = -INFINITY;
for (uint c = tid; c < n; c += nthr) m = max(m, float(xr[c]));
m = tg_reduce<true>(m, scratch, lane, sg, nsg);
float s = 0.0f;
for (uint c = tid; c < n; c += nthr) s += metal::exp(float(xr[c]) - m);
s = tg_reduce<false>(s, scratch, lane, sg, nsg);
for (uint c = tid; c < n; c += nthr) out[row * n + c] = T(metal::exp(float(xr[c]) - m) / s);
```
:::

## 测完之后

Apple M2 实测（fp16，2048 行）：

| N | `mx.softmax` | 你的实现 |
|---|---|---|
| 1024 | **310 us** | 640 us |
| 4096 | **716 us** | 1152 us |
| 32000 | 4432 us | **4032 us** |

- 行较短时 MLX 更快：它的 softmax 在行能放进寄存器时只读一次输入（“looped” 和 “single row” 两种实现），而你的三遍写法要读三次。行很长时（32000，词表大小）两者都受带宽限制，你的反而略快。
- 改进一：**online softmax**，像 T5 那样一遍同时维护 (m, s)，读取次数从 3 次降到 2 次。
- 改进二：每个线程一次读 4 个连续元素（`vec<half, 4>` 或手动展开），减少指令数。
- 读源码：MLX 的 `mlx/backend/metal/kernels/softmax.h` 和 `rms_norm.metal`，对照它们是怎么选择每行线程数和单遍 / 多遍实现的。

::: answer 面试追问：simd_sum 和 CUDA 的 warp shuffle 归约有什么区别？
语义上，`simd_sum` 相当于一整轮 butterfly 归约（`__shfl_xor_sync` 5 轮）：simdgroup 内所有 lane 都得到结果。CUDA 里你通常手写这 5 轮，或者使用 `cg::reduce` / CUB 的 WarpReduce；Metal 直接提供了这条内建函数，还有 `simd_prefix_inclusive_sum`、`simd_shuffle_xor` 等更底层的操作。跨 simdgroup 的部分在两边完全一样：写进共享内存（threadgroup 内存），同步，再归约一次。
:::
