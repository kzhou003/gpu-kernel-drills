lede: 在 Apple GPU 上走一遍 C4 的路线：先用 threadgroup 内存做 tiling，再换成 simdgroup_matrix 8×8 矩阵指令，性能翻倍，并且看清和 MLX 自带的 steel GEMM 还差在哪里。

## 背景

Apple GPU 没有 NVIDIA 那样的大块 Tensor Core MMA，它的矩阵加速单位是 **simdgroup_matrix**：一个 simdgroup（32 个线程）协作持有一个 8×8 的矩阵，`simdgroup_multiply_accumulate` 一次完成 8×8×8 的乘加。MLX 的 GEMM（“steel” kernel，`mlx/backend/metal/kernels/steel/`）、attention 和量化 matmul 都建立在它上面。M5 起，GPU 里还加入了 neural accelerator，MLX 源码中对应 `*_nax` 系列 kernel。

## 要用到的知识

- **threadgroup tiling**（与 C4 v1 相同）：16×16 的 threadgroup 计算 C 的一个 16×16 块，A、B 的 tile 放进 threadgroup 内存，每个值复用 16 次。
- **simdgroup_matrix**：

```c++
#include <metal_simdgroup_matrix>                     // 通过 metal_kernel 的 header= 传入
simdgroup_float8x8 a, b, c = make_filled_simdgroup_matrix<float, 8, 8>(0.0f);
simdgroup_load(a, ptr, row_stride);                   // 从 threadgroup / device 内存加载一个 8×8 块
simdgroup_multiply_accumulate(c, a, b, c);            // c = a @ b + c
simdgroup_store(c, ptr, row_stride);
```

  ptr 指向这个 8×8 块的第一个元素，row_stride 是这块数据在内存中的行跨度（以元素计）。
- 本题的分工：一个 threadgroup 有 128 个线程（4 个 simdgroup，排成 2×2），计算 C 的 32×32 块；每个 simdgroup 负责一个 16×16 的四分之一，持有 2×2 个 8×8 累加器；BK = 16，每个 K 块做两步 8 宽的 MMA。
- 二维 grid：MLX 的 `grid` 是线程数，所以 `grid = (128 · N 方向的 tile 数, M 方向的 tile 数, 1)`，`threadgroup = (128, 1, 1)`；kernel 里用 `threadgroup_position_in_grid.xy` 定位 tile。
- 边界：tile 加载时越界部分填 0；累加器先 `simdgroup_store` 到 threadgroup 内存，再由 128 个线程按 mask 写回 C。

::: callout analogy 32 个人合抬一块拼图板
`simdgroup_matrix` 是一个 simdgroup（32 个线程）合力持有一块 8×8 的拼图板，一条指令把两块板相乘再加到第三块上。一个 threadgroup 的 4 组人各拼 4 块（2×2），合起来就是 C 的一个 32×32 区域。MLX 的 steel GEMM 让每组人同时拼更多块，复用更多，所以更快。

## 提示

::: hint 1 先完成 tiled 版本
它和 C4 的 `matmul_smem_kernel` 几乎逐行对应：`threadIdx` → `thread_position_in_threadgroup.xy`，`blockIdx` → `threadgroup_position_in_grid.xy`，`__syncthreads()` → `threadgroup_barrier(mem_flags::mem_threadgroup)`。
:::

::: hint 2 simdgroup 版本的地址
threadgroup 内存用一维数组：`As[32 * 16]`（行跨度 BK = 16），`Bs[16 * 32]`（行跨度 BN = 32）。simdgroup `sg` 负责的四分之一：`sg_r = sg / 2`，`sg_c = sg % 2`。

```c++
simdgroup_load(a0, As + (sg_r * 16 + 0) * 16 + kk, 16);   // A 的两个 8 行块
simdgroup_load(a1, As + (sg_r * 16 + 8) * 16 + kk, 16);
simdgroup_load(b0, Bs + kk * 32 + sg_c * 16 + 0, 32);     // B 的两个 8 列块
simdgroup_load(b1, Bs + kk * 32 + sg_c * 16 + 8, 32);
```
:::

::: hint 3 主循环
```c++
for (uint k0 = 0; k0 < K; k0 += 16) {
    for (uint e = tid; e < 512; e += 128) { /* 加载 As[e] 和 Bs[e]，越界填 0 */ }
    threadgroup_barrier(mem_flags::mem_threadgroup);
    for (uint kk = 0; kk < 16; kk += 8) {
        /* 4 次 simdgroup_load */
        simdgroup_multiply_accumulate(c00, a0, b0, c00); simdgroup_multiply_accumulate(c01, a0, b1, c01);
        simdgroup_multiply_accumulate(c10, a1, b0, c10); simdgroup_multiply_accumulate(c11, a1, b1, c11);
    }
    threadgroup_barrier(mem_flags::mem_threadgroup);
}
/* 4 次 simdgroup_store 到 Cs，barrier，按 mask 写回 C */
```
:::

## 测完之后

Apple M2 实测（fp32，单位 TFLOP/s）：

| n | MLX steel GEMM | 你的 tiled | 你的 simdgroup_matrix |
|---|---|---|---|
| 512 | 0.80 | 0.29 | 0.57 |
| 1024 | 2.19 | 0.37 | 0.79 |
| 2048 | **2.62** | 0.39 | 0.79 |

- simdgroup_matrix 比纯 threadgroup tiling 快 2 倍左右，但还只有 MLX 的 30%。差距在哪：MLX 的 steel GEMM 每个 simdgroup 持有更多累加器（更大的寄存器 tile，复用度更高），用双缓冲把下一块的加载和当前块的计算重叠，并且在 threadgroup 内存的布局上做了避免 bank conflict 的处理。这和 C4 → T4 的经验完全一致。
- 实验：把每个 simdgroup 的累加器从 2×2 增加到 4×2（每个 threadgroup 计算 64×32），观察寄存器压力和速度的变化。
- 读源码：`mlx/backend/metal/kernels/steel/gemm/` 中的 `mma.h` 和 `loader.h`，对照你自己的实现。
- 量化 matmul（`mx.quantized_matmul`，4-bit 分组量化）是 Mac 上跑 LLM 的主力：decode 时它是 memory-bound 的 `qmv`，prefill 时是 `qmm`。读一读 `quantized.h`，看反量化是怎么和乘加融合在一起的。

::: answer 面试追问：Mac 上跑 LLM，prefill 和 decode 的瓶颈分别是什么？
prefill 是 compute-bound 的，受 GPU 的矩阵吞吐限制（M2 的 fp16 大约只有几 TFLOP/s，比数据中心 GPU 低两个数量级），所以长 prompt 的首 token 延迟较高。decode 是 memory-bound 的，每个 token 都要读一遍全部权重，速度约等于“内存带宽 ÷ 模型字节数”：4-bit 量化的 7B 模型约 3.5–4 GB，在 100 GB/s 的 M2 上理论上限约为每秒 25 个 token，在 800 GB/s 的 Ultra 上约为每秒 200 个。所以 Mac 上最有效的优化是量化（减少字节数）和投机解码（读一次权重，验证多个 token）。
:::
