lede: CUTLASS 3/4、CuTe DSL、FlashAttention-3/4、DeepGEMM 和 FlashInfer 的 CuTe-DSL kernel 都建立在同一套“布局代数”上。用纯 Python 实现它的六个核心操作，以后读 CuTe 代码时就能把每个 layout 当成一个函数来读。

## 背景

G1 的 BlockedLayout 描述“张量元素如何分给线程”。CuTe 把这件事推广成一种统一的数学对象：**Layout = (Shape, Stride)，是一个从坐标到偏移的函数**。线程到数据的映射（TV layout）、MMA 指令要求的寄存器排列、shared memory 的 swizzle、一个 tile 怎么切成更小的 tile，全部用 layout 和它们之间的运算表达。写 Hopper / Blackwell 上的高性能 kernel（wgmma、TMA、tcgen05）基本绕不开 CuTe，而 CuTe DSL（CUTLASS 4 的 Python 前端）让这件事可以直接在 Python 里完成：FlashAttention-4 全部用它写成，FlashInfer 0.7 也有大量 `cute_dsl` 后端。

## 要用到的知识

- **记号**：`(4,2):(1,4)` 表示 shape (4,2)、stride (1,4)，即 4×2 的列主序矩阵；`(4,2):(2,1)` 是行主序。
- **调用**：坐标 `(i, j)` → `i·1 + j·4`。整数下标先按**列字典序**（第一个模式变化最快）拆成坐标：下标 5 在 shape (4,2) 中对应 (1, 1)。shape 可以嵌套：`((2,2),2):((1,4),2)`。
- **size** = shape 中所有数的乘积；**cosize** = 最大偏移 + 1。
- **coalesce**：函数不变，模式数最少。去掉大小为 1 的模式；若 `stride_{i+1} == shape_i · stride_i`，两个模式可以合并成一个。
- **composition** `A ∘ B`：`R(i) = A(B(i))`。用 B 的布局去“选取” A 中的元素：tiling、对数据重新排列都是 composition。
- **complement** `complement(A, M)`：A 在 `[0, M)` 中留下的“空隙”的布局。A 和它的 complement 合起来恰好铺满 `[0, M)`。
- **logical_divide** `A ⊘ B = A ∘ (B, complement(B, size(A)))`：把 A 切成“每块由 B 选出的元素”（模式 0）× “块的重复”（模式 1）。CuTe 里的 `zipped_divide`、`local_tile` 都建立在它上面。

## 提示

::: hint 1 先写调用，再写 coalesce
`_idx2crd` 对每个模式依次做 `idx % size(mode)`、`idx //= size(mode)`；嵌套模式就递归。`coalesce` 只需要遍历 flatten 之后的 (shape, stride) 对：维护结果列表，能合并就合并到最后一个模式上。
:::

::: hint 2 composition 的单模式算法
对 B 的一个模式 `s:d`（rest_shape = s，rest_stride = d），遍历 coalesce 后 A 的每个模式 `(a_s, a_d)`（最后一个模式除外）：

```text
new_shape  = min(max(1, a_s // rest_stride), rest_shape)
若 new_shape != 1：结果加入模式 new_shape : rest_stride · a_d
rest_shape  //= new_shape
rest_stride = ceil(rest_stride / a_s)
```
剩下的 rest_shape 放在 A 的最后一个模式上：stride 为 `rest_stride · A 最后一个模式的 stride`。
:::

::: hint 3 complement
```text
modes = sorted((stride, shape) for 每个 shape != 1 的模式)
current = 1
for (d, s) in modes:  结果加入 (d // current) : current;  current = s · d
结果加入 ceil(cotarget / current) : current，最后 coalesce
```
例：`complement((2,2):(1,6), 24)` → `(1,3,2):(1,2,12)` → coalesce 得到 `(3,2):(2,12)`。
:::

## 测完之后

- 用你的实现算一算：一个 128×64 的行主序 tile，按 `(32, 8)` 分块之后，第 3 块的第 5 个元素在原 tile 中的偏移是多少？这正是 `local_tile` 做的事。
- 读 CuTe DSL 的官方示例（CUTLASS 仓库 `examples/python/CuTeDSL/`），从 elementwise add 开始：它用 `zipped_divide` 把张量切成每个线程负责的小块，你现在可以手算出每个线程拿到哪些元素。
- **swizzle**：shared memory 的 bank conflict 通常不是靠 padding（C3 的做法）解决，而是对地址做异或：`Swizzle<B, M, S>` 把地址的第 [M+S, M+S+B) 位异或到第 [M, M+B) 位上。它也是一个“布局”，可以和别的 layout 组合。
- 进阶：在 RTX 5090 上安装 `nvidia-cutlass-dsl`（FlashInfer 0.7 已经依赖它），跑通一个 CuTe DSL 的 elementwise kernel，再读 FlashInfer 中 `flashinfer/cute_dsl/` 下的一个 kernel。

::: answer 面试追问：CuTe 的 layout 抽象解决了什么问题？
高性能 kernel 里有很多种“坐标 → 地址”的映射：全局内存中的张量、shared memory 中带 swizzle 的 tile、MMA 指令要求的寄存器排列、每个线程负责的数据片段。传统写法把这些映射都写成手工的下标公式，每换一种指令或 tile 大小就要重写，也很容易出错。CuTe 把它们统一成 (Shape, Stride) 函数，并提供 composition、divide、product 等运算来推导映射，例如“这块 tile 中线程 t 的第 v 个值在哪里”就是几个 layout 运算的组合。这样，同一份 kernel 代码可以换 tile 大小和 MMA 指令，编译器在编译期算出全部下标。
:::
