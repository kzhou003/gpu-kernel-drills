lede: 一行一个 program，整行放进一个 block：数值稳定的 softmax 只读一次、写一次。这是“融合 reduction”的标准写法。

## 背景

softmax 出现在 attention、MoE 路由、采样（logits → 概率）里。PyTorch 的通用实现要把同一行读好几次（求 max、求 exp 的和、归一化）。行不太长（比如词表维度之外的大多数情况，N ≤ 几千）时，整行可以放进一个 program 的寄存器里：**读一次 → 在片上完成 max / exp / sum / 除法 → 写一次**。

## 要用到的知识

- **数值稳定**：`softmax(x) = softmax(x − max(x))`。减去最大值后最大的指数是 e⁰ = 1，不会溢出。不减的话 x = 100 时 fp32 的 e¹⁰⁰ ≈ 2.7e43 已经接近上限，fp16 在 x > 11 时 eˣ 就溢出了。
- **行内归约**：`tl.max(x, axis=0)`、`tl.sum(x, axis=0)` 作用在整个向量上，返回标量。
- **mask 的填充值要服务于运算**：做 max 时，padding 位置应该是 −inf，这样它不会成为最大值，exp(−inf) = 0 也不会计入 sum。
- **stride**：行与行之间的距离是 `x.stride(0)`，切片后可能不等于 N。
- `BLOCK_SIZE = triton.next_power_of_2(N)`；行越长，`num_warps` 越大。
- `tl.program_id(0).to(tl.int64)`：大张量下 `row * stride` 可能超过 int32。

## 提示

::: hint 1 五行
row 起点 → load（other=−inf，转 fp32）→ 减 max → exp → 除以 sum → store。
:::

::: hint 2 常见坑
- `other=0.0` 而不是 `-inf`：某一行全为负数时，padding 的 0 会成为 max，而且 exp(0 − max) 也会被算进分母。
- 用 `n_cols` 代替 stride 来定位行：切片得到的输入（stride 300、N 257）会读错。
- 输出 stride 与输入 stride 混用：输出是新分配的连续张量，用 `out_row_stride`。
:::

::: hint 3 kernel 主体
```python
row = tl.program_id(0).to(tl.int64)
cols = tl.arange(0, BLOCK_SIZE)
mask = cols < n_cols
x = tl.load(in_ptr + row * in_row_stride + cols, mask=mask, other=-float("inf")).to(tl.float32)
x = x - tl.max(x, axis=0)
num = tl.exp(x)
y = num / tl.sum(num, axis=0)
tl.store(out_ptr + row * out_row_stride + cols, y.to(out_ptr.dtype.element_ty), mask=mask)
```
:::

## 测完之后

- 有效带宽按 `2 × M × N × 2 字节`（fp16 读一次、写一次）计算。RTX 5090 上 M = 4096 的实测：

| N | torch.softmax | 参考解 |
|---|---|---|
| 256 | 6.8 us | 8.2 us（更慢） |
| 1024 | 16.4 us | **11.9 us** |
| 4096 | 65.5 us · 1025 GB/s | **43.6 us · 1540 GB/s** |
| 16384 | 180 us | 178 us |

  N = 256 时每行只有 512 字节，一行一个 program 太碎，调度开销占主导（见下面“一个 program 处理多行”）。
- N = 16384 时，一行 16K 个 fp32 值要放进寄存器，每个线程要持有很多值。观察寄存器溢出和性能下降。
- **超长行怎么办**：把行分成若干段，用 **online softmax** 在一次遍历中维护 `(m, l)`：遇到新的一段，`m_new = max(m, max(段))`，`l = l·exp(m − m_new) + Σexp(段 − m_new)`。T5 的 FlashAttention 用的就是这个公式。
- 一个 program 处理多行（grid 只开 SM 数 × k 个 program，用 `tl.range` 循环），可以减少短行时的调度开销：这是官方 tutorial 的进阶写法。

::: answer 面试追问：fused softmax 为什么比 PyTorch 快？快的上限在哪？
softmax 是 memory-bound 的，时间 ≈ 搬运字节数 / 带宽。融合后每个元素只读写各一次，这就是下限，所以上限就是“读一次 + 写一次”在峰值带宽下所需的时间。行变得非常长、一个 block 放不下时，要么分两遍（多读一次），要么用 online softmax 在一次遍历中完成。
:::
